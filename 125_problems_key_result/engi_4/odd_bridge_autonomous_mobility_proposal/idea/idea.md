# Idea Agent - ODD-Bridge Portfolio

## Evidence-constrained problem

The Survey rejects the premise that a fleet-share target alone can prove the realism of an all-self-driving future. A safety argument must survive an ODD change, degradation, interaction with non-ADS road users, loss or corruption of connected support, and a public/governance review. The research target is an assurance-gated transition, not a claim of technological inevitability.

## Candidate portfolio

## Selected idea: ODD-Bridge

**ODD-Bridge** means **Operational Design Domain Bridging with assurance, recovery, and legitimacy evidence**. Its research unit is:

`service x ODD card x traffic-mix card x sensing/degradation card x connectivity/infrastructure card x safe-state/recovery card x assurance evidence card x public/governance card`.

An expansion is not expressed as “deploy everywhere.” It is a named delta between an approved ODD and a candidate ODD: for example, a new roadway class, time condition, weather/visibility envelope, speed range, intersection type, traffic mix, or service operation. Each delta has to show which previous evidence is portable, which risks are new, how a failure is detected, how the system reaches a safe state, and whether the affected public has been given an understandable operating and data-governance account.

## Hypothesis and falsifiers

**H-ODD-001.** An ADS mobility service can make more credible scaling decisions when every ODD expansion is gated by linked technical assurance, degraded-mode recovery, mixed-traffic, infrastructure/connectivity, monitoring, and public-legitimacy evidence, rather than by aggregate fleet miles or a component benchmark alone.

The idea is downgraded when any gate cannot be satisfied: the scenario argument cannot distinguish an old ODD from the new condition; a sensor/map/software/connectivity loss lacks a safe state; local behavior fails to remain safe when connected support disappears; a human fallback is needed but cannot be shown appropriate for the transition; an incident-learning process cannot preserve traceability; privacy/responsibility/access effects are hidden; or the expansion claim relies on evidence from another operator, city, vehicle, or route without an explicit transfer rationale.

## Simulated idea evolution

1. Root: install better perception and expand an autonomous fleet.
2. Mechanism repair: make the ODD delta, not the fleet count, the unit of deployment change.
3. Safety repair: join every delta to degradation detection, minimal-risk behavior, and post-event traceability.
4. Systems repair: classify infrastructure/V2X as required, assistive, or unavailable, then require safe local operation for each declared status.
5. Legitimacy repair: add public, privacy, responsibility, accessibility, and operational-communication evidence before scale approval.

ODD-Bridge is selected because it can be falsified, it respects the Survey evidence boundaries, and it produces a practical design protocol without claiming road operation or future exclusivity.
