# 综述草稿保存与断点恢复

综述生成、修订、定稿、导出和评估分别记录进度。末尾步骤失败时，已完成正文保留在磁盘，运行结果标记为 `requires_review`，可以下载草稿并继续处理失败步骤。

## 保存的文件

以下路径相对于本次综述的 `BasicInfo.base_dir`。适配入口使用工作区的 `survey/output`；批处理入口按主题和模型隔离，保存在 `BasicInfo.base_dir/survey_drafts/<标识>/`，避免不同主题覆盖草稿。

| 文件 | 内容与写入时机 |
| --- | --- |
| `survey_draft.json` | 当前可用正文、章节结构、草稿状态和未解决问题。并行请求每完成一个正文单元就写入，单节通过校验后再次保存。 |
| `survey_draft.md` | 可直接阅读的当前稿；失败时带“待复核草稿”标记及问题清单。 |
| `draft.json`、`draft.md` | 完整初稿一生成就保存，后续修订保留这份初稿。整体字数或追溯完整性检查失败也保留已经生成的正文。 |
| `survey_status.json` | `requires_review` 或 `completed`、失败阶段、已完成阶段、问题描述和草稿路径。 |
| `checkpoints/survey_checkpoint.json` | 输入指纹、逐节原始响应与校验状态、最新草稿、阶段进度、失败历史、定稿与评估结果。 |
| `checkpoints/runtime.json` | 检索研究上下文、活动文献 ID、参考文献图、已读笔记、摘要及本地材料对应的 SH 元数据。 |
| `checkpoints/database.pt` | 文献及标题向量索引。恢复时直接加载，避免重新构建索引。 |

JSON、Markdown 和检查点均通过临时文件、刷盘和原子替换写入；向量索引也原子替换。JSON 是恢复数据源，重启时根据检查点重建 Markdown。每个并行请求的响应在整批请求结束前保存，因此其他请求超时或进程中断不会抹掉已返回的正文。操作系统强制结束进程时，正在生成且尚未返回的响应需要重做。

## 修订或导出失败

修订基于已保存正文的副本执行。修订抛出异常时保留上一份正文；修订模块返回人工复核问题时，也交付当前可用稿。句子补丁的标题、引用和证据校验仍然生效，其失败原因写入问题清单。

工作流将待复核结果记录为 `PARTIAL`，在产物列表保留初稿、当前稿及状态文件。网页在运行过程中也可以列出已经写出的草稿。后续 Idea、实验设计和 Author 阶段等待综述完成，避免将待复核稿当作完成的证据交接。

## 如何继续运行

在相同输出目录、相同研究输入下再次运行原命令，入口先读取检查点，跳过检索、深读、聚类、分析和提纲生成。恢复顺序为：

1. 正文未完成：复用已保存的正文响应，仅请求缺失或正文校验失败的单元；追溯元数据失败时继续元数据修复。
2. 修订未完成：复用已完成修订阶段；受证据约束的章节质量审阅复用已完成章节，仅重审失败章节。
3. 定稿已完成、导出失败：直接复用定稿及引用列表，重试导出。
4. 导出已完成、评估失败：仅重试评估。已导出文件缺失或内容变化时，先重新导出已保存定稿。

通过预设自动分配输出目录的独立 Survey 入口，会查找输出根目录下输入指纹相同的最近一次未完成运行，并继续使用其目录。指定新的 `BasicInfo.survey_run_id` 或新的完整输出路径可以开始新运行；已完成运行不会被自动选作未完成检查点。

科学工作流重试失败的 Survey 时会把上一 attempt 的路径传入 `SurveyStageRequest.resume_dir`。新 attempt 复用正文与阶段进度，并复制检索交接文件及分析产物；正式导出绑定新 attempt 的运行身份。显式使用 `--restart-from survey --force` 会开始新的综述生成过程。

直接运行综述脚本时，也可在配置中指定上次输出目录：

```yaml
survey:
  BasicInfo:
    survey_resume_dir: /path/to/previous/survey/attempt-001
```

命令行入口支持 `python -m src.cli survey --config <原配置> --resume <上次目录>`；未传 `--topic` 时使用检查点的主题。默认主题命令会寻找匹配的未完成运行。传入额外 Hydra 覆盖参数时，使用 `--resume` 明确选择续跑目录。要重新生成综述，可用 `--run-id <新标识>`。

独立 Survey 配置使用顶层 `BasicInfo.survey_resume_dir`。当前目录已有检查点时优先使用当前目录的最新进度。检查点的研究主题、研究上下文、材料及正文约束与输入不符，或检查点损坏时，恢复会报错并保留原稿。更换研究输入时使用新输出目录；不要清空旧目录来重试修订。

尚未写入检查点的旧运行无法通过本功能恢复。模块初始化仍会加载所需模型，恢复省去的是已完成的检索、分析、正文生成及修订请求。

## 验证

`tests/test_survey_delivery.py` 使用故障注入覆盖分节中断、阶段失败、失败稿交付、新实例恢复、跨 attempt 恢复、向量索引恢复、逐节质量审阅续跑及网页产物枚举。`tests/test_science_workflow.py` 验证待复核稿阻止下游运行，以及重试时传入上次的检查点目录。测试使用本地模型替身，不调用真实 LLM 或 MinerU 服务。
