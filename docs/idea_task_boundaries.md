# Idea Agent 的任务边界与具体决策

用户的原始请求确定研究对象、目标、明确限制和交付内容。LLM 在这个任务中探索机制、假设和方法；Survey 提供证据与文献覆盖信息。

## 输入与保存

Idea 输入解释器提取 `task_contract`，包括：

- `original_request`：完整原始请求，解释器失败时也保留。
- `task_mode`：`idea_generation`、`idea_refinement` 或 `protocol_design`；局部修订模式需要对应原文引句或显式修改范围。
- `required_deliverables`：用户要求的交付内容。
- `user_constraints`：用户明确提出的限制。
- `problem_premises`：用户提供的问题前提。

提取的交付内容、限制和前提必须有原文中实际存在的 `source_quote`。运行时使用原文作为要求，忽略模型新增的要求。显式配置的 `refinement_scope` 单独记录来源。

契约写入 Idea attempt 的 `task_contract.json` 和 artifact 的 `run.task_contract`。它随高级分析、MCTS 生成与评价、后续修订和 JSON 修复传递。各阶段仍遵守自己的输出结构；涉及科学决策时，对照原始请求给出具体回答。

`--input` 的完整请求保留在契约中。绑定 Survey 时，解释器改写的主题标题可以与 Survey 标题不同；用户显式提供的 `--topic` 仍执行已有的主题一致性检查。

## 约束来源

`config_explicit`、`input_explicit`、`user_explicit` 和 `explicit` 来源的范围作为明确限制。输入解释器声称显式、但无法在原文找到的范围降为推断。

`input_inferred`、`analysis_grounded` 等范围放入 `proposed_scope`，作为可修改的研究建议。高级分析生成的范围不会覆盖用户限制，单个候选的研究重点也不会变成全局硬边界。

Survey 的 `constraints` 不再回填成 `hard_constraints`，`field_consensus` 不再回填成 `verified_facts`。交接的来源校验与科学结论是否已经验证分别处理。

## 允许具体提出设计和预测

科研提示词区分文献事实、用户前提、设计选择、假设、预测和观测结果。

模型可以提出拟定参数、候选机制和可检验预测，并说明选择依据与验证办法。文献报道值、实测结果、来源和引用仍需真实支持。尚未验证的预测应保留预测状态，并完成用户要求的判断。

高级分析按任务类型工作：局部修订遵守用户的修改范围；方案设计给出具体选择与方法；想法生成探索任务内的机制和替代路径。默认阶段分工不会删除用户明确要求的科学决策。

## 契约校验与局部修复

`field_consensus`、`existing_problems`、`evaluation_gaps`、`future_directions`、反例、检索查询、引用和目标缺口可以为空。存在 Survey 交接不会强制每个想法关联缺口。

方案正文、方法、机制链与验证目标仍须完整。提供缺口 ID 时，校验其是否存在于选定交接文件。修复提示要求保留有效决策、证据与任务覆盖，只调整报告的问题及其依赖字段；现有重试次数保持有界。

缺口分流的兜底路径继续执行资格过滤，避免把 `verification_only`、`supporting_constraint` 或 `exclude` 项重新送入主想法生成。

后续辩论也允许没有目标缺口或额外假设，不再根据空数组制造缺陷和泛泛的反对意见。高级分析不会仅因候选出现验证、诊断或控制类词语而自动丢弃改进。最终对齐阶段继续区分明确修改范围与模型建议，并保留用户要求的选择和预测。

## 交接数据与版本

传给模型的 Survey 交接保留普通字段及其嵌套内容，使用深拷贝避免修改原始交接。运行控制字段 `constraints` 与科学任务要求分开，Survey 的 `scope` 以 `survey_coverage` 表示文献覆盖范围。原始交接保留在运行上下文供来源与状态校验，文件及指纹不被重写。

科研 PromptSpec 更新为 `1.1.0`，使用允许显式设计值的规则，并关闭公共旧禁令的重复叠加。注册表同时保留 `1.0.0` 及其原始哈希语义。

新建运行使用新科研规则。已经冻结 `research_policy` 的运行继续使用原快照；恢复旧运行不会自动改写冻结策略。已启动的 Python 进程也不会热加载这些修改。

## 验证

回归测试覆盖原文保存、要求的引文核验、推断范围不会升级成硬约束、无缺口的有效设计、未知缺口 ID、局部契约修复、MCTS 上下文传递、交接字段保留与深拷贝，以及科研提示词的旧版本兼容。
